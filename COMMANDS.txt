 PARK PATROL - COMMANDS
Run all commands from the project folder (parkpatrol-server).


SETUP (first time only)
-----------------------
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-camera.txt   (server + camera tools)
python scripts/setup_env.py
python scripts/telegram_setup.py
tools/ngrok config add-authtoken YOUR_NGROK_TOKEN


RUN
---
Activate environment:       source .venv/bin/activate
Start server (local):       python main.py
Start server + public URL:  ./scripts/start_public.sh   (old ngrok setup)
Start camera + detection:   python scripts/tracker.py   (setup: --calibrate)
Video only (no detection):  python scripts/send_frame.py
Simulate tracker:           python scripts/test_tracker.py
Notification demo:          python scripts/demo_notify.py


STOP
----
Stop a running command:     Ctrl + C
Stop server and tunnel:     pkill -f main.py; pkill -f "ngrok http"

CAMERA (EVERYTHING ON THE MAC: PHONE -> OBS -> VIRTUAL CAMERA)
-------------------------------------------------------------
1. Open OBS. In Sources, add your phone (e.g. "Video Capture Device" ->
   your iPhone, or your phone camera app's source) and frame the diorama.
2. OBS > Settings > Video: Base and Output resolution 1280x720, FPS 15.
3. Click "Start Virtual Camera" (Controls panel, bottom right).
4. In .env:                 CAMERA_SOURCE=OBS Virtual Camera
   (picked by name, so it still works when other cameras connect)
5. Start the camera feed:   python scripts/send_frame.py
List cameras the script sees:  python scripts/send_frame.py --list
First run: macOS asks to allow camera access for your terminal app. Allow it
(System Settings > Privacy & Security > Camera).
No OBS streaming, MediaMTX, or second laptop needed anymore.


SPOT DETECTION (scripts/tracker.py)
-----------------------------------
One-time setup (redo if the camera or diorama moves):
1. python scripts/tracker.py --calibrate
2. R, then click the 4 corners of the covered parking, in this order:
     1. A1 end, road side     2. A1 end, back
     3. A6 end, back          4. A6 end, road side
3. Remove ALL cars and objects, then press E (corners + empty-lot snapshot).
4. Teach it what a toy car is (it only counts toy cars, not other objects):
     C = "these are cars": park toy cars in the spots, press C.
         Do this for EVERY toy car you will use, in a few spots/angles.
     O = "these are NOT cars": put other things in the spots (eraser, pen,
         coin, phone, paper, keys...), press O. More variety = better.
   Press each 4-6 times, moving things between presses. Watch the live
   boxes: cars turn grey, other objects show "item". Q when done.

Run (this replaces send_frame.py - it detects AND sends the video):
  python scripts/tracker.py           report spots to the website
  python scripts/tracker.py --show    same, plus a live window with scores
  python scripts/tracker.py --forget  delete all taught examples and start over
A car must stay put ~1.5 s before it is reported.
Double parking = one car on a bay's yellow line (parked across OR parallel):
both spots in that bay become a violation. Non-car items never count.

Tuning (only if detection is wrong): edit "thresholds" in
data/lot_calibration.json while watching --show:
  spot          lower = more sensitive to something being in a spot
  edges         lower = catches dark cars more easily
  straddle      share of a line that must be covered to call double parking
  car_match     how closely an object must match a taught car (shown as car~0.00)
Taught examples are saved as pictures in data/examples/ (good for your report).
Taught something wrong (e.g. pressed C with a pine cone in a spot)? Delete that
picture from data/examples/ and restart the tracker: it re-learns from what's left.
Also teach the double-parking positions: park a car across a line (and parallel
along it) and press C, so those views are learned too.
If the room lighting changes a lot, retake the empty snapshot (step 3).


DATABASE (XAMPP MySQL)
----------------------
1. Open XAMPP (manager-osx) > Manage Servers > start "MySQL Database"
   (start "Apache Web Server" too if you want phpMyAdmin)
2. phpMyAdmin:              http://localhost/phpmyadmin
3. Start the server as usual (python main.py). It creates the
   "parkpatrol" database and all tables automatically.
   Or import database/schema.sql from phpMyAdmin's Import tab.
4. Settings live in .env:   DB_HOST, DB_PORT, DB_USER, DB_PASSWORD, DB_NAME
   DB_ENABLED=false         run without MySQL
If MySQL is off, the site still works; history just isn't saved.


WEBSITE ON RENDER
-----------------
The public site runs on Render and redeploys by itself after every push:
  git add -A && git commit -m "What changed" && git push
Render settings live in the Render dashboard (Environment tab), not in .env.

Send the camera to Render (set in .env on the camera laptop):
  TRACKER_SERVER_URL=https://YOUR-APP.onrender.com
  CAMERA_FPS=3              keep this low: video uses Render's monthly bandwidth
Then run:                   python scripts/send_frame.py

Do NOT run python main.py locally while Render is live with the same
TELEGRAM_BOT_TOKEN: two copies of the bot fight over Telegram messages.
Free plan: the site sleeps after 15 min without traffic (~1 min to wake).


DATA ENCRYPTION
---------------
Personal data in MySQL (admin email/name/photo, Telegram chat IDs, violation
snapshots) is encrypted with AES-256-GCM. Sign-in logs keep only ok / invalid.
The key is DATA_ENCRYPTION_KEY in .env and in Render (same value in both).
New key:                    python scripts/generate_key.py
BACK UP THE KEY. Without it the encrypted data can never be read again.
Never commit it or store it in the database.


OPTIONAL .env SETTINGS
----------------------
CAMERA_SOURCE=...           camera name (OBS Virtual Camera), number, or rtsp:// link
CAMERA_FPS=15               frames per second sent to the server
CAMERA_WIDTH=640            frame width in pixels (larger = sharper, more data)
NOTIFY_COOLDOWN_MINUTES=0   no cooldown between subscriber notifications (rehearsals)
TRACKER_SERVER_URL=...      server address used by the scripts (default http://localhost:8000)


LOT MAP DESIGN (FIGMA)
----------------------
The lot map on the website is drawn from static/lot-map.svg, designed in Figma.
1. Import:  drag static/lot-map.svg onto a Figma canvas (it becomes editable layers).
2. Design:  change anything - colours, road, park, trees, gazebo, labels.
            Keep the six spot layers named exactly A1 ... A6 (A1 = top spot),
            one layer (or group) per spot. Their live colours come from the website.
3. Export:  select the top frame > Export > SVG, and under the export options
            check "Include 'id' attribute" (keeps the A1..A6 names).
4. Replace static/lot-map.svg with the exported file, then publish:
            git add -A && git commit -m "Update lot map design" && git push
Check locally first with python main.py and open http://localhost:8000.
If a spot layer is missing or renamed, the browser console says which one.
